# 版本号规则（用户定稿）

**格式：`MAJOR.MINOR.PATCH`** —— 三段纯数字：

| 位置 | 含义 | 什么时候加 |
|---|---|---|
| 第 1 位 `MAJOR` | **大版本** | 架构级改动、不兼容升级 |
| 第 2 位 `MINOR` | **小版本** | 向下兼容的新功能 |
| 第 3 位 `PATCH` | **补丁** | 向下兼容的修复、文案、样式 |

## 细则
- **必须**是三段纯数字；**不允许** `v` 前缀、第四段、字母占位（`2.0`、`v2.0.0`、`2.0.0.1` 都不合规）。
- 预发布可追加独立标识：`2.0.0-rc5`（`rc5` 不是第 4 段，只表示"2.0.0 的第 5 个候选"）。
- 递增时**丢弃**预发布标识：`2.0.0-rc5` + patch → `2.0.1`；+ minor → `2.1.0`；+ major → `3.0.0`。
- 比较必须**按数字逐段**：`0.3.10 > 0.3.9`、`2.0.0-rc10 > 2.0.0-rc5`、`2.0.0 > 2.0.0-rc5`
  （禁止用字符串比较，否则 `rc10 < rc5` 这种错判会导致更新通道失效）。
- 两个面板（芮拓面板 / MC 开服面板）**同一规则**。

## 代码落点
- `backend/app/version.py`：`parse / validate / is_valid / bump / compare / is_newer`；
- 构建脚本入口调用 `validate(VERSION)`，不合规**直接失败**，不产出包；
- 自测：`python backend/app/version.py` 应打印 `[OK] version.py 自测通过`。
