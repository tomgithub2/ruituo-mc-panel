# 芮拓MC面板

打开浏览器就能建服、开服、看状态、导建筑、备份回滚、分配权限的 Minecraft 多实例管理面板。

后端 FastAPI + SQLite，前端纯 HTML/CSS/JS（**没有构建步骤**，后端直接托管 `frontend/dist/`）。
一个进程、一个数据库文件，解压即跑，不依赖任何外部服务。

**许可**：[AGPL-3.0-or-later](LICENSE)。

---

## 它解决什么问题

不用装客户端、不用游戏账号、不用在聊天窗里贴命令。

- 一台机器上开多个服，各自独立端口、独立内存、独立目录
- 实时控制台、可编辑的 `server.properties`、在线改配置
- 建筑文件一键导入（BDX / 结构文件 → Java 命令方块）
- 定时备份、一键回滚
- 玩家、白名单、OP、封禁、权限组
- 谁在什么时候动了什么，都有审计记录

## 安全

这一节是重点。面板等于把服务器的命令行搬到了浏览器里，**它本身的攻击面必须当成生产系统对待**。

### 账号与口令

| 项 | 实现 |
|---|---|
| 口令存储 | **PBKDF2-HMAC-SHA256，600,000 次迭代**，每账号 16 字节随机盐；库里只有 `盐$哈希`，没有任何可逆存储 |
| 口令强度 | 至少 12 位，需包含大写 / 小写 / 数字 / 符号中的任意三类 |
| 初始账号 | 首次启动生成 `admin`，随机口令**只在服务端本地终端打印一次**，不写日志、不写库、不通过接口返回 |
| 监听地址 | 手动运行默认只监听 `127.0.0.1`；`install.sh` 为了能远程访问会绑 `0.0.0.0`，可用 `--bind` 改 |
| 登录防爆破 | 默认 **5 次失败锁定 10 分钟**，阈值与时长可配；锁定按「用户名 + IP」计 |
| 口令修改 | 改口令会**递增该账号的 `token_epoch`**，此前签发的所有会话立即失效，所有设备强制重新登录 |

### 会话

- 会话令牌用 `secrets` 生成，只在登录响应里下发一次，前端存 `localStorage`
- 每次请求校验「令牌 + 账号状态 + `token_epoch`」，停用账号或改口令即刻失效
- 令牌不写在 URL、不写进日志；审计里只记录账号与 IP

### 权限

四级，按最小权限分配：

| 角色 | 能做什么 |
|---|---|
| 超级管理员 | 全部功能，含账号管理、面板设置 |
| 管理员 | 实例的创建 / 启动 / 停止 / 配置 / 文件，不能改账号 |
| 普通用户 | 只能操作分配给自己的实例 |
| 只读 | 只能看，不能改 |

另有按账号的**实例配额**（数量、内存）与**接口权限**双重校验：前端隐藏按钮只是体验，后端每个接口都会独立验权。

### 文件与路径

- 所有文件接口先把路径 `realpath`，再校验它必须落在**该实例目录**之内，`..`、绝对路径、软链接逃逸一律拒绝
- 解压（Java 运行时、更新包）时**逐成员检查**：拒绝绝对路径、`..` 穿越、指向目标目录之外的链接
- `backend/data/`（库、配置、世界、备份）不对外暴露任何直接读取的接口

### 更新包

面板的远程更新是**可验证**的，不依赖 HTTPS 单点信任：

1. 清单 `latest.json` 必须通过 **RSA（PKCS#1 v1.5 + SHA-256）验签**，签名覆盖清单里除 `signature` 外的全部字段
2. 通过后再**逐文件比对 sha256**；清单里没有的文件不动
3. 任何一步不符 → 判定失败，**按备份回滚**，不留在半套代码
4. 公钥内置在 `backend/app/license_public.pem`，私钥不在仓库里

### 审计

登录成功/失败、账号变更、实例启停、配置修改、文件删除、备份与回滚、更新应用，全部落库并带 IP 与时间。审计记录**只增不改**，面板里可按时间与账号查。

### 部署建议

- **不要把 8100 直接暴露到公网**。用 Nginx / Caddy 反代，只开 443，并在反代上做 HTTPS
- 面板进程用**专用低权限系统账号**运行；只有 `java` 子进程需要读写实例目录
- `backend/data/` 只给该账号可写，备份目录建议放独立磁盘
- RCON 只监听 `127.0.0.1`，口令与面板口令**不要复用**
- 定期导出 `backend/data/`（含库与配置）到面板之外的位置

## 快速开始

### 一键安装（Linux）

```bash
curl -fsSL https://www.rt888.icu/install_mc.sh | bash
```

装完在终端会打印初始口令，浏览器打开 `http://<服务器IP>:8100` 即可。

### 手动运行

```bash
python3 -m venv venv
venv/bin/pip install -r backend/requirements.txt
venv/bin/python backend/run.py
```

要求 Python 3.10+；Java 运行时可在面板里一键安装，也可以指定已有的 `java`。

### Windows

```powershell
python -m venv venv
venv\Scripts\pip install -r backend\requirements.txt
venv\Scripts\python backend\run.py
```

## 目录结构

```
backend/
  app/            业务代码（路由、认证、实例、更新、建筑导入）
  tools/          运维脚本（重置口令、自检、样例生成）
  requirements.txt
  run.py          启动入口
frontend/dist/    静态站点（无构建，直接托管）
  css/ js/ pages/
install.sh        一键安装
panelctl          命令行管理（起停、日志、备份）
docs/VERSIONING.md  版本号规则
```

运行期数据都在 `backend/data/`：`mc.db`（账号、实例、审计）、`config.json`（面板配置）、实例目录、备份归档。

## 版本号

`大版本.小版本.补丁`

- 第 1 位：有破坏性变更（升级后要改配置、迁数据）
- 第 2 位：新增功能，老用法照旧
- 第 3 位：只修问题

判定细节见 [docs/VERSIONING.md](docs/VERSIONING.md)。

## 自检

```bash
python tools/design_lint.py     # 界面规范：无渐变/发光、令牌集中、线性图标、左对齐
python backend/selftest.py      # 后端自检
```

`design_lint` 会在界面里混入渐变、彩色外发光、实心图标或散落的颜色字面量时直接报错并指出文件行号。

## 已知限制

- 单机部署，不做多节点调度；多实例靠端口与目录隔离
- SQLite 单文件，写入并发上限取决于磁盘；上千实例请改用外部数据库（需自行改造）
- 面板必须能管理 Java 进程，容器化部署时注意 PID 命名空间
- 建筑导入支持 BDX 与常见结构文件，不支持的 NBT 结构会明确报错而不是静默跳过
